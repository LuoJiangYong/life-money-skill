# 访谈指南 — L1 建档

## 目标

在进入 7 轮分析前，产出一份经用户确认的 `profile.json`（Contract 1）：真实、完整、无编造。

**流程**：材料收集（门禁 1 前半）→ 材料解析 → 访谈补全 → 确认收口（门禁 1 后半）→ 定稿 profile.json。

---

## 一、材料请求（门禁 1 前半）

向用户请求以下材料，并说明用途与隐私（"材料只在本机用于生成报告，不会上传"）：

| 材料 | 必需性 | 用途 |
|---|---|---|
| 简历（PDF / Word / 文本均可） | 强烈建议 | 经历、技能、成果的骨干来源 |
| 项目报告 / 结项材料 | 可选 | 挖掘「被低估」隐藏技能的关键素材（分析 1） |
| 作品集 / 作品文档 | 可选 | 技能证据与可变现资产盘点 |
| 绩效 / 晋升材料（如有） | 可选 | 成果数字与外部评价 |

## 二、材料解析规则

1. **只提取，不推断**：材料里写的才进入字段；模糊处标记待确认，不自行补全。
2. **数字原样保留**：成果数字、时间、职级用材料原文，不得改写量级。
3. **冲突处理**：材料与访谈冲突时，以用户口述为准，并在门禁 1 确认时向用户当面澄清。
4. 解析结果先落草稿，与访谈结果合并后再定稿。

## 三、访谈问题清单（材料里没有的才问）

按 `career_profile.schema.json` 字段组织；原则：**材料已覆盖的不重复问**。

### identity
- 现在的职位 / 身份？行业、城市？
- 工作几年了？当前状态（在职 / 待业 / 自由职业 / …）？

### salary（敏感字段）
- 当前收入：税前还是税后？按月还是按年？含奖金吗？
- （如愿意）构成比例：基本工资 / 奖金 / 补贴？
- 提示用户：此信息仅用于分析口径，不出现在报告正文。

### work_history（逐段补全）
- 每段经历：公司、角色、起止时间、主要负责什么？
- **成果追问**："有没有具体数字？增长多少 / 覆盖多少人 / 省了多少钱 / 做到什么规模？"
- 这段经历主要用到哪些技能？

### skills
- 最拿手的技能 3-5 个？各打几分（1-5）？有什么证明？
- 还熟悉哪些工具、领域、语言、证书？

### time_budget
- 每周能**稳定**拿出多少时间探索变现？（现实值，不是理想值）
- 时间上的硬约束（加班季、家庭、竞业）？

### goals
- 最想解决什么？（用用户原话记录，不翻译成术语）
- 风险偏好：保守（尽量不影响主业）/ 中等 / 积极（愿意投入更多资源）？

### constraints
- 竞业协议、签证、家庭安排等硬约束？

## 四、门禁 1 收口检查（不可跳过）

1. **必填齐全**：identity / salary / work_history / skills / time_budget / goals 无缺项；缺项追问，不猜测。
2. **摘要确认**：向用户展示结构化摘要（经历时间线 + 技能 + 目标 + 收入口径），问"有没有要修正的？"
3. **定稿**：用户确认后写入 `projects/<run>/profile.json`（`meta.source` 标注 interview / resume / mixed）。
4. **定稿后仅两处可增补**：门禁 2 写入 `income_target`、门禁 3 写入 `launch_hours_per_week`；其余字段不再变动。

## 反模式

- ❌ 材料里有的字段重复问一遍（浪费用户耐心）
- ❌ 用户没说的数字"合理估计"填上
- ❌ 跳过确认直接进入分析
- ❌ 把访谈变成闲聊，收不到结构化数据
