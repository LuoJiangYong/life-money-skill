# 分析规格 — 7 轮分析

## 执行总则

1. **顺序固定**：1 隐藏技能 →【门禁 2】→ 2 收入机会 → 3 变现路径 → 4 最大杠杆 → 5 高薪方向 →【门禁 3】→ 6 AI 副业 → 7 90 天计划。
2. **可回溯**：重要结论要能指向 profile 的具体字段（经历 / 技能 / 目标）；无法回溯的判断写入 `summary.assumptions`，或删除。
3. **个性化底线**：把用户的具体经历写进结论——同一条建议，能说出「因为你在 X 的经历」才算合格。
4. **宁缺毋滥**：数量目标达不到时如实少给并在 assumptions 说明；禁止编造凑数。
5. **语言**：中文；面向用户本人，务实、直接、不鸡血。

---

## 门禁 2 — 收入目标（分析 1 后、分析 2 前）

**时机**：分析 1（隐藏技能）完成后——先让用户看到「我有什么」，再定「我想要多少」。

**执行**：
1. 展示分析 1 的 2-3 条关键发现（让用户看到挖掘结果）。
2. 提问："你希望副业 / 变现每月额外带来多少收入？"
3. 选项：`1000-3000 元（默认推荐）`/ `3000-5000 元` / `5000-10000 元` / 自定义区间。
4. 用户不选时采用默认 1000-3000 元/月，并告知「可随时调整」。
5. 写入 `profile.goals.income_target = { min_amount, max_amount, currency: "CNY", period: "monthly" }`。

**下游影响**：分析 2 的「收入潜力」全部对齐该区间口径（可覆盖 / 部分覆盖 / 需组合）。

---

## 分析 1 — 发现隐藏技能 → `hidden_skills`

- **视角**：识别用户「低估」的技能——不是罗列他会什么，而是找出「他觉得理所当然、但市场会付钱」的能力；从项目报告、业余成果、跨领域组合里优先挖。
- **输出**（每条）：name / why_valuable / who_pays / ai_monetization / evidence
- **目标**：10 条（最少 5）

**质量标准**：
- name 具体到可交易：「跨境独立站 Google Ads 投放诊断」✓；「运营能力」✗
- who_pays 写人群画像：「做 DTC 出海、月广告费 5 万左右的小团队负责人」✓；「企业客户」✗
- evidence 指向 profile 的具体经历
- ai_monetization 给可执行路径：「用 AI 批量生成竞品广告文案变体，作为诊断服务的附加交付物」✓

**反模式**：❌ 性格词（沟通能力 / 学习能力强）→ 换成能卖钱的动作；❌ 十项全是同类技能 → 至少覆盖「主业延伸 / 跨界组合 / 兴趣变现」三个方向。

---

## 分析 2 — 寻找收入机会 → `income_opportunities`

- **输入**：profile + 前序 +【门禁 2 收入目标】
- **输出**（每条）：title / description / startup_cost / time_investment / difficulty / income_potential / first_step
- **目标**：10 条（最少 5）

**质量标准**：
- 真实可达：启动成本与用户时间预算匹配；不推荐需要全职投入的方案
- income_potential 与目标对照：「稳定后 1500-3000 元/月，可覆盖目标区间」
- difficulty 用 低 / 中 / 高；数字口径用 CNY（或用户所在市场）
- first_step 是「本周可执行的第一个动作」：「把过去 3 个项目复盘整理成一页服务介绍」✓
- 给出 `potential_level`（1-5，相对用户目标区间的收入潜力量级）——报告机会矩阵图使用

**反模式**：❌ 画饼（「月入过万不是梦」）；❌ 十条全是自媒体（多样性：服务型 / 技能型 / 资产型）；❌ 与用户技能无关的通用副业清单。

---

## 分析 3 — 变现我的经验 → `monetization_paths`

- **视角**：企业战略家——把用户当作「一人企业」，盘点可产品化的资产线。
- **输出**（每条）：type（服务 / 咨询产品 / 数字产品 / 自由职业）/ name / description / target_customer / pricing_hint
- **目标**：≥3 条，覆盖至少 2 种 type

**质量标准**：与 hidden_skills 形成「能力 → 产品」映射（不是重复罗列技能）；pricing_hint 给区间与依据（「按次 300-800 元，参考同城同类服务」）。

**反模式**：❌ 只给一种类型；❌ 与收入机会列表重复（此处是「打包成什么产品」的层次）。

---

## 分析 4 — 最大杠杆机会 → `leverage`

- **输出**：focuses[1-3]，按 rank 排序；每条 focus + rationale
- **质量标准**：
  - rank 1 明确回答「如果只做一件事」
  - rationale 基于用户约束推理：「你每周只有 X 小时 + 已有 Y 资源，所以先做 Z——它在 30 天内能出第一笔收入」
- **反模式**：❌ 三条并列无排序；❌ 选「最好」而非「最省力见效」；❌ rationale 悬浮（「前景好」）。

---

## 分析 5 — 向我展示什么薪水更高 → `higher_pay_roles`

- **输出**（每条）：role_or_industry / why_higher_pay / qualification / pay_gap（如有校准数据）
- **目标**：≥3 条

**质量标准**：
- qualification 用 profile 的具体资历说话（哪段经历 / 技能使其胜任）
- pay_gap 只在有【市场校准】数据时给出，并标注口径与来源
- 有校准或可靠行业依据时，给出 `pay_monthly_low` / `pay_monthly_high`（月薪数值）——报告薪酬阶梯图使用；无依据则省略，不编造
- 覆盖「横向行业迁移」与「纵向职级升级」两类

**反模式**：❌ 推荐与用户经验断层的赛道；❌ 无来源的精确薪资数字；❌ 忽略地域市场（用用户城市口径）。

---

## 门禁 3 — 每周启动时间（分析 5 后、分析 6 前）

**时机**：分析 5 完成后、分析 6 开始前。

**执行**：
1. 提问："为了启动副业，你每周能稳定投入多少小时？"（默认 6 小时）
2. 说明用途："这决定我给你推荐多大规模的副业方案。"
3. 写入 `profile.time_budget.launch_hours_per_week`（用户不调整则用 6）。

**下游影响**：分析 6 的所有 `weekly_hours` 必须 ≤ 该值。

---

## 分析 6 — 创建 AI 驱动的副收入来源 → `ai_services`

- **输入**：profile + 前序 +【门禁 3 每周时间】
- **输出**（每条）：name / description / weekly_hours / price_hint
- **目标**：5 条（最少 3）；weekly_hours ≤ 门禁 3 值

**质量标准**：
- 服务具体到可定价交付物：「用 AI 给中小企业做公众号月度内容包（10 篇/月）」
- AI 是「效率杠杆」而非卖点本身：说明用 AI 把哪一步从 X 小时缩到 Y 分钟
- 与用户技能挂钩；优先复用分析 1-5 里出现的能力

**反模式**：❌ 「用 AI 做自媒体」式笼统；❌ 时间估算超过门禁 3 值；❌ 追热点但与用户无关的项目。

---

## 分析 7 — 90 天计划 → `plan_90d`

- **输出**：goal_statement + phases[3]（第 1-30 / 31-60 / 61-90 天；每条：name / focus / actions / milestone）
- **质量标准**：
  - 与分析 4（杠杆）对齐：第一阶段先启动 rank 1 杠杆点
  - actions 每阶段 2-4 条，具体可检验（「约谈 5 个潜在客户并记录反馈」）
  - milestone 是本阶段验收标准（可判定）：「确定 1 个付费方向并收到首笔定金」
- **反模式**：❌ 「学习相关知识」式空动作；❌ 三阶段无递进；❌ 计划与前面的分析脱节。

---

## 收尾 — summary 与 assumptions

- `summary.highlights`：3-6 条，跨维度提炼「最值得记住的发现」（不是各章标题复述）。
- `summary.assumptions`：所有推断性判断在此声明（如「未检索到可靠行业数据，分析 2 的收入区间为定性估算」）。
- 完成后校验 `career_analysis.schema.json` 的必填项与数量约束，再交渲染。
